④ / REVIEW
Risk-tiered review inbox 风险分级收件箱 Review
The single gate for every write — clipboard import and MCP write-back both queue here. Grouped by risk: low (default-on) / medium / high (default-off + warning). 02 Product architecture · Three layers 产品架构 · 三层

How it holds together 这些东西怎么连在一起

Presentation
Presentation 表现层
  • Interaction · user experience path交互 · 用户体验路径 The main page flow: Bootstrap (first-run onboarding) → Dashboard (pick a project, see current goal + recent sessions) → Copy Prompt → paste into external AI → paste AI's response back → Review → save. Each screen focuses on one primary action to reduce decision load.主页面流转: Bootstrap(首次引导) → Dashboard(选项目、看当前目标 + 最近对话) → 复制指令 → 粘到外部 AI → 把 AI 的回复粘回来 → Review → 保存。每一屏聚焦一个主要动作，降低决策负担。
  • UI · visual style + brandUI · 视觉风格 + 品牌 Notion-style slate; bilingual EN/CN toggle; all core operations one screen deep.Notion 风格 slate 蓝灰;中英一键切换;所有核心操作一屏到达。
Logic
Logic 逻辑层
  • Business logic · the path that solves the pain业务逻辑 · 解决痛点的路径 Core insight: the user is the only entity that exists across all AI tools, so the user is the bridge. End a session: user picks what to carry; start the next: MemoryOS assembles it into a prompt the next AI can read; import: AI's response gets parsed and staged for review; review: AI suggests updates, user approves every write. Memory stays current: AI marks what's outdated in each handoff (Superseded), the app merges new over old, stale decisions retire. The next AI always gets up-to-date context.核心思路：用户是唯一同时存在于所有 AI 工具里的实体，所以让用户当桥。结束对话：用户选要带走什么；开始下一段：MemoryOS 把它拼成下一个 AI 能读的 prompt；导入：AI 的回复被解析、分组待审；审核：AI 建议更新，用户亲手确认才写盘。记忆保持现时：AI 在 handoff 里标出过时内容（Superseded），app 把新旧合并、过时决策退场。下一个 AI 拿到的永远是最新上下文。
  • Algorithm · how the modules connect算法 · 模块之间的衔接 Prompt assembly: pack user's context files + standardised prompt template into clipboard. Fault-tolerant parser: recognise headings with or without ##, numbered / bold / plain-text / indented variants, zh + en section names — never assume the AI's output is perfectly formatted. Risk router: categorise each suggested update as low / medium / high risk, decide what's default-on vs default-off in Review. Superseded merge: AI marks outdated content in the handoff → parser extracts → Review shows old (strikethrough) vs new (highlighted) → user confirms → stale memory retires.Prompt 组装: 把用户的上下文文件 + 标准化指令模板打包进剪贴板。容错解析: 有无 ##、数字 / 粗体 / 纯文本 / 带缩进的标题都认, 中英文段名都认，不假设 AI 输出格式完美。风险路由: 把每条建议更新标为低 / 中 / 高风险, 决定 Review 里哪些默认勾、哪些默认不勾。Superseded 合并: AI 在 handoff 里标注哪些旧内容已过时 → parser 提取 → Review 页划线对比新旧 → 用户确认 → 过时记忆退场。
Data
Data 数据层
  • Business data · what flows through the product业务数据 · 在产品里流转的内容 about_me.md: the user's long-term identity and preferences, shared across all projects. 00_context.md: per-project working snapshot, updated after each session. decisions.md: key decisions accumulated over time. sessions/*: timestamped per-session summaries. These four file types are the product's entire data model. Input to the next prompt, output from the last AI, the user's accumulated working memory.about_me.md：用户的长期身份和偏好，跨项目共享。00_context.md：每个项目的工作快照，每次对话结束后更新。decisions.md：积累的关键决策记录。sessions/*：按时间戳存的每次对话总结。这四种文件就是产品的全部数据模型。上一次 AI 的输出变成下一次 prompt 的输入，用户的工作记忆就这样积累起来。
  • Feedback channel反馈通道 In-app feedback button: user writes a note → one click copies it to clipboard and opens GitHub Issues — paste and submit. No network call from MemoryOS, no backend, no account needed.App 内反馈按钮: 用户写一段文字 → 一键复制到剪贴板并打开 GitHub Issues 页面, 粘贴提交即可。MemoryOS 不发任何网络请求, 不需要后端, 不需要账号。
02.5 Memory freshness · Four-layer breakdown 记忆现时性 · 四层拆解

How memory stays current 记忆如何保持现时

The hardest part isn't recording — it's retiring what's outdated. Four layers, each with a clear input → process → output. 最难的不是记录，是让过时的内容被替换掉。四层架构，每层都有明确的 输入 → 处理 → 输出。
