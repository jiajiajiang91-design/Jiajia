02 Product architecture · Three layers 产品架构 · 三层

How it holds together 这些东西怎么连在一起

Presentation
Presentation 表现层
  • Interaction · user experience path交互 · 用户体验路径 The main page flow: Bootstrap (first-run onboarding) → Dashboard (pick a project, see current goal + recent sessions) → Copy Prompt → paste into external AI → paste AI's response back → Review → save. Each screen focuses on one primary action to reduce decision load.主页面流转: Bootstrap(首次引导) → Dashboard(选项目、看当前目标 + 最近对话) → 复制指令 → 粘到外部 AI → 把 AI 的回复粘回来 → Review → 保存。每一屏聚焦一个主要动作，降低决策负担。
  • UI · visual style + brandUI · 视觉风格 + 品牌 Notion-style slate; bilingual EN/CN toggle; all core operations one screen deep.Notion 风格 slate 蓝灰;中英一键切换;所有核心操作一屏到达。
Logic
Logic 逻辑层
  • Business logic · the path that solves the pain业务逻辑 · 解决痛点的路径 Core insight: the user is the only entity that exists across all AI tools, so the user is the bridge. Each project's memory is distilled into one page of cards under 1200 characters; the AI reads it at session start and drafts an updated version at session end. Updates go through the inbox; the user confirms what's saved. Memory stays current: outdated entries are archived, never deleted, and the next AI always gets the latest page.核心思路：用户是唯一同时存在于所有 AI 工具里的实体，所以让用户当桥。每个项目的记忆浓缩成一页 1200 字内的卡片：AI 开场读这一页，结束时起草新版。更新经收件箱，用户确认后入库。记忆保持现时：过时条目归档而不删除，下一个 AI 拿到的永远是最新一页。
  • Algorithm · how the modules connect算法 · 模块之间的衔接 Prompt assembly: pack the memory cards + a standardised prompt template into the clipboard. Fault-tolerant parser: recognise headings with or without ##, numbered / bold / plain-text / indented variants, zh + en section names — never assume the AI's output is perfectly formatted. Source tagging: the user's decisions and the AI's suggestions are extracted into separate channels, so a suggestion can never be saved as a decision. Card merge: parser extracts the updated card page → review shows old (strikethrough) vs new (highlighted) → user confirms → superseded entries move to the archive.Prompt 组装：把记忆卡片 + 标准化指令模板打包进剪贴板。容错解析：有无 ##、数字 / 粗体 / 纯文本 / 带缩进的标题都认，中英文段名都认，不假设 AI 输出格式完美。来源分流：用户的决定和 AI 的建议被解析进不同通道，建议不可能被存成决定。卡片合并：parser 提取卡片新版 → 确认页划线对比新旧 → 用户确认 → 被替代的条目移入历史档案。
Data
Data 数据层
  • Business data · what flows through the product业务数据 · 在产品里流转的内容 about_me.md: the user's identity and preferences, shared across projects. cards.md: one page of memory cards per project — what the AI reads first, updated after each session. decisions.md: the archive where superseded entries go. sessions/*: timestamped session summaries. These four file types are the product's entire data model: the last AI's output becomes the next AI's input.about_me.md：用户的身份和偏好，跨项目共享。cards.md：每个项目一页记忆卡片，AI 开场读的就是它，每次对话后更新。decisions.md：决策档案，被替代的条目去这里。sessions/*：按时间戳存的对话总结。这四种文件就是产品的全部数据模型：上一个 AI 的输出变成下一个 AI 的输入。
  • Feedback channel反馈通道 In-app feedback button: user writes a note → one click copies it to clipboard and opens GitHub Issues — paste and submit. No network call from MemoryOS, no backend, no account needed.App 内反馈按钮: 用户写一段文字 → 一键复制到剪贴板并打开 GitHub Issues 页面, 粘贴提交即可。MemoryOS 不发任何网络请求, 不需要后端, 不需要账号。
02.5 Memory system · From the PRD 记忆系统 · 出自 PRD 功能架构

Four modules of memory 记忆系统的四个模块

The architecture follows the three common stages of LLM memory systems (write, update, read), plus a measurable evaluation layer. 架构参照大模型记忆系统的通用三段机制（写入、更新、读取），再加一层可量化的验收。

4M
01 Write写入 · WRITE
Structured Handoff结构化交接 Session output sorted into facts / decisions / suggestions / next starting point按事实、决策、建议、起点四类整理本次输出
Source Tracking来源标记 Every decision carries a date and its original wording; an AI idea is never recorded as the user's call每条决策附日期与原话出处；AI 的想法不会被写成用户的决定
02 Update更新 · UPDATE
Consolidation记忆整合 New progress merges into current status; one latest version per topic新进展并入当前状态，同一主题只留最新版
Conflict Resolution冲突处理 When old and new conflict, the old decision is voided with a pointer to its replacement新旧矛盾时旧决策作废，留下指向新版的指针
Forgetting as Archiving遗忘即归档 Superseded entries leave the first page but are never deleted被替代的条目退出第一页，但永不删除
03 Read读取 · READ
Hierarchical Injection分层注入 The one-page summary is always loaded; details fetched on demand概要常驻一页，细节按需检索
Token Budget上下文预算 Opening injection capped at 1200 characters; overlong context makes models overlook the middle开场注入限 1200 字；注入太长，模型会忽略中段内容
04 Evaluation验收 · EVALUATION
Three-question test三问测试 A fresh AI must answer in 30s: who am I and how do we work / where is the project / where do we start today全新 AI 30 秒内答对：我是谁怎么协作 / 项目到哪了 / 这次从哪开始
Cold-start check冷启动对照 Tested in a no-background chat: injection halved, all three questions answered correctly无背景新对话实测：注入量降到原来一半以下，三问全对
02.6 Business flow · From the PRD 业务流程 · 出自 PRD

The flow is a closed loop 业务流程是一个闭环

Every step's output is the next step's input. The end of one session prepares the start of the next, in any AI. 每一步的出口都是下一步的入口。这次对话的结束，就是下次对话（任何 AI）的开场准备。

03 Critical path · The end-session loop 关键流程 · 结束对话的回路

Now: one MCP call drops the session into the inbox 现在：一条 MCP 指令，记忆直接进收件箱
