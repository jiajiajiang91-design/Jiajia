02 产品定位 · 不是聊天，是工作台

工作台 vs 聊天工具

CHATGPT / CLAUDE

理解和生成

  • 核心对话框里读懂你，给出高质量回答
  • 交互你问，它答；你提需求，它写
  • 产物文本、代码、图片——留在对话框内
  • 壁垒模型能力：推理、上下文、多模态
KIMI

接管真实工作现场

  • 核心自然语言 → 工作流 → 交付物
  • 交互你说任务，它规划、调工具、操作网页
  • 产物PPT、网站、表格、代码——直接可交付
  • 壁垒工具集成深度 + agent 执行可靠性
Office 按文件类型分：Word、Excel、PPT。Kimi 按任务完成链路分：理解需求 → 调工具 → 生成产物 → 交付。
03 商业模式 · C 端入口 → 工作台订阅 → 占住入口

赌"agent 工作量"收费

01
免费获客
查资料、做 PPT、读 PDF、发帖——让用户养成习惯。免费额度筛出高频工作用户。
02
Agent 付费转化
¥49 → ¥699/月，统一额度池。不按聊天次数收费，按"agent 干了多少活"收费。
03
占住工作入口
资料、网页、文档、表格、代码、发布后台，都从 Kimi 开始。不卖模型，占入口。
数据印证：MAU 回落 → 免费用户在流失。付费用户月增 170%、ARR 单月翻倍 → agent 工作台的付费转化正在发生。

05 风险 + Claw × MemoryOS

三个命门 + 四维差异

THREE RISKS
RISK 01

模型能力会反咬工作流

Claude Computer Use、OpenAI Operator 追上后，用户可能回流到模型更强 + agent 也够用的平台。

RISK 02

浏览器操作不是深护城河

技术形态可复制（Playwright + LLM）。壁垒在操作可靠性，不在架构独占。

RISK 03

一次性自动化留不住人

"做个 PPT"做完就走。真正留住人的是"它记得我的一整套工作方式"。

CLAW × MEMORYOS
维度KIMI CLAWMEMORYOS
生态 Kimi 内部长期 agent 跨 AIChatGPT / Claude / Cursor
控制 Agent 状态对话间接影响 本地 MarkdownObsidian 直接打开
冲突 Agent 判断旧记忆出错不可见 人类确认旧划线 · 新高亮
位置 执行层"帮我跑任务" 治理层"我是谁 · 项目到哪了"
ELEVATOR PITCH
MemoryOS 解决的是 Kimi 这类 agent 工作流的"连续性问题"：当用户在 Kimi、Claude、ChatGPT、Codex 之间切换时，工作上下文不会跟着丢。不是替代 Kimi，而是补上它做真实工作流时很需要的一层——本地、可见、可编辑、可确认的跨 AI 记忆层。

当每个 AI 都有自己的记忆时，用户自己的工作记忆应该放在哪里？
