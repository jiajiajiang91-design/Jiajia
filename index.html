01.A
Shipped Product · MemoryOS · v0.1.1 Windows Binary 已交付产品 · MemoryOS · v0.1.1 Windows 安装包

One local memory file, take it into any AI yourself 一份本地的工作记忆,可以自己带进任何 AI 工具

Read case study ↗阅读 Case Study ↗

One layer below the tool-switch annoyance: AIs each have strengths but don't share memory, so collaboration never compounds. MemoryOS takes a "user-bridged" route — write key points at session end, carry them into the next session in any tool. Most basic shape one person could ship at this stage: local file, AI drafts updates, user confirms each write. Later iterations may change it. The 5 decisions, and the kind of user feedback that would disprove them, are in the case study.

换工具麻烦的下一层问题是: 不同 AI 各有所长但互不通气,协作累积不起来。MemoryOS 选了"用户主动桥接"这条路——对话结束时把要点写下来,下一段对话在哪个 AI 里都能带回去。当前最朴素的形态: 记忆文件存在本地、AI 起草更新、用户确认每一次写入。这是一个人在当前阶段能搭出来的样子,后续迭代可能会变。详细的 5 个决策、以及什么样的用户反馈会推翻它们,见 Case Study。

From planetary cement metabolism down to a single 8×8 cell at Dagenham Dock, the thesis is laid out as one explorable interface. Three scales of evidence — planetary, national, site — feed into an algorithmic pipeline where each remediation step is traceable: why this site, why this strategy, why this spatial layout. The algorithm provides comparable, iterable design evidence; the final spatial judgement remains with the designer.

The Entropy Atlas — the n8n-orchestrated evidence layer of ~1,000 East-London post-industrial sites — is included inside this thesis as the site-evidence layer.

从全球水泥产业的行星级代谢，到 Dagenham Dock 上一格 8×8 网格的具体判断，整个毕设被整理成一个可逐步探索的界面。三个尺度的证据——行星、国家、场地——接入一条算法链路，让每一步治理过程可追溯：为什么选这个场地、为什么分配这种策略、为什么是这个空间布局。算法提供的是可比较、可迭代的设计证据；最终的空间判断仍由设计者完成。
