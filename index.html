Daily switching between ChatGPT / Claude / Cursor — none of them remember what happened in the others. 01.A
Shipped Product · MemoryOS · v0.2.0 Windows Binary 已交付产品 · MemoryOS · 接入MCP

A local memory your AI reads directly — every write-back goes through your review 自动化收集工作记忆，AI 直接读取——每一次写回都先经你审核

Read case study ↗阅读 Case Study ↗

One layer below the tool-switch annoyance: AIs each have strengths but don't share memory, so collaboration never compounds. MemoryOS keeps that memory as local files you own. v0.2.0 closes the loop both ways: the AI now reads a project's memory directly through an MCP server (live in Claude Desktop today), and when it wants to write something back, that update lands in a review inbox — nothing touches your memory until you confirm it. The clipboard bridge still works for any AI that can't speak MCP yet. The key product decisions, and the kind of user feedback that would disprove them, are in the case study.

换工具麻烦的下一层问题是: 不同 AI 各有所长但互不通气,协作累积不起来。MemoryOS 把这份记忆做成你自己电脑里的本地文件。v0.2.0 把闭环两头都打通了：AI 现在能通过 MCP server 直接读取某个项目的记忆（已在 Claude Desktop 里跑通），当它想写回什么时，更新会先进「记忆收件箱」——你不确认，就不会动到正式记忆。还不支持 MCP 的 AI，依旧能用剪贴板桥接。详细的产品决策、以及什么样的用户反馈会推翻它们,见 Case Study。

02

Competitive Analysis — MemoryOS × mem0A side-by-side test of two cross-AI memory tools 竞品分析 — MemoryOS × mem0两个跨 AI 记忆工具的逐项实测

Hands-on test of mem0 / OpenMemory (YC-backed, the closest product in this direction) across three task flows — cross-AI recall, memory organisation, user control. In my test, mem0's three entry points each stored memory in their own space and didn't combine into one shared context. My takeaway: cross-entry memory consistency still isn't a solved problem — that doesn't prove MemoryOS is right, only that the position is worth working on. 亲手测 mem0 / OpenMemory（YC 投资、方向最接近的产品）—— 跨 AI 召回、记忆整理、用户控制权三条任务流。在我的测试里，mem0 的三个入口各自存到自己的空间，跨入口的记忆没有串成一份统一上下文。我的判断是：跨入口的记忆一致性，目前仍是个没被很好解决的问题——这不证明 MemoryOS 的方向就对，只是说明这个位置值得做。

Programming Decay — Algorithmic Remediation硕士毕设 / 可追溯的场地修复链路 Programming Decay — 算法驱动的场地修复硕士毕设 / 可追溯的场地修复链路

My MArch thesis treats post-industrial contamination not as a one-time cleanup but as a design problem unfolding across three scales — from the planetary footprint of cement, through UK industrial corridors, down to a single site at Dagenham Dock. An algorithmic pipeline (GIS evidence → K-Means site selection → four remediation strategies → Pix2Pix spatial generation → Neural CA temporal evolution) makes each step traceable and explainable; the final spatial judgement remains with the designer. In product terms: turning scattered spatial evidence into a traceable, step-by-step decision workflow. 硕士毕设把后工业污染场地的修复重新定义为一个跨尺度的设计问题——从水泥产业的行星级污染足迹，经英国工业走廊，落到 Dagenham Dock 一块具体场地。一条算法链路（GIS 证据 → K-Means 选址 → 四种修复策略 → Pix2Pix 空间生成 → Neural CA 时间演化）让每一步治理过程可追溯、可解释；最终的空间判断仍由设计者完成。换成产品语言：把零散的空间证据，整理成一条可追溯、可逐步推进的决策流程。

From planetary cement metabolism down to a single 8×8 cell at Dagenham Dock, the thesis is laid out as one explorable interface. Three scales of evidence — planetary, national, site — feed into an algorithmic pipeline where each remediation step is traceable: why this site, why this strategy, why this spatial layout. The algorithm provides comparable, iterable design evidence; the final spatial judgement remains with the designer.

The Entropy Atlas — the n8n-orchestrated evidence layer of ~1,000 East-London post-industrial sites — is included inside this thesis as the site-evidence layer.

从全球水泥产业的行星级代谢，到 Dagenham Dock 上一格 8×8 网格的具体判断，整个毕设被整理成一个可逐步探索的界面。三个尺度的证据——行星、国家、场地——接入一条算法链路，让每一步治理过程可追溯：为什么选这个场地、为什么分配这种策略、为什么是这个空间布局。算法提供的是可比较、可迭代的设计证据；最终的空间判断仍由设计者完成。

Entropy Atlas（熵图集）—— 由 n8n 自动化抓取的东伦敦约 1,000 处后工业场地证据层 —— 已作为证据数据源嵌入在该交互页内部。
