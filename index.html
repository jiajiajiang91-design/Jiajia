01

MemoryOS — Cross-AI Memory Layer跨 AI 的本地工作记忆 / 桌面 app MemoryOS — 跨 AI 工作记忆层本地优先的桌面 app

Knowledge work increasingly runs across several AIs at once — each one stronger at something. The real problem is making them collaborate, and today they can't: no AI remembers another's context. There are several ways to attack this (unified front-ends, API bridges, cloud sync); MemoryOS takes the memory-layer route, and deliberately keeps it local, cross-vendor and user-controlled — because the existing options either lock memory inside one vendor (ChatGPT Memory) or host it in yet another cloud (Notion AI). Defined, built and shipped solo. 知识工作越来越同时跑在多个 AI 上——因为每个 AI 各有所长。真正要解决的是"让它们协作"，而当下做不到：AI 之间互不记得彼此的上下文。解决方向有好几条（统一入口、API 打通、云端同步），MemoryOS 选择从记忆层切入，并刻意做成本地、跨厂商、用户掌控——因为现有方案要么把记忆锁死在单一厂商（ChatGPT Memory），要么托管到又一个云（Notion AI）。从定义、开发到上线由一人完成。

01.A
Shipped Product · MemoryOS · v0.1.1 Windows Binary 已交付产品 · MemoryOS · v0.1.1 Windows 安装包

One working memory, across every AI tool 一份工作记忆，贯穿每一个 AI 工具

Read case study ↗阅读 Case Study ↗

The real problem sits one level above the tool-switch annoyance: people now rely on multiple AIs precisely because each is good at different things, but those AIs share no memory, so the collaboration never compounds. Several routes could close this gap — unified clients, API integrations, cloud sync. MemoryOS takes one of them: a shared memory layer that ends a session by writing down the key points, and carries them into the next session in any tool. The bet is on which route, not just the feature.

Once the memory-layer route was chosen, two decisions defined its shape: (1) the memory file lives on the user's own machine, not in any vendor account — nobody wants their notes scattered across different companies' servers; (2) the AI drafts updates but the user approves every single write — trust collapses the moment an AI silently edits your notes. Designed, built and shipped end-to-end by one person; the case study unpacks all five decisions and what kind of user feedback would disprove them.

真正的问题在"换工具麻烦"之上一层：人们之所以依赖多个 AI，正是因为它们各有所长，但这些 AI 之间没有共享记忆，协作因此无法累积。弥补这个断层有好几条路——统一客户端、API 集成、云端同步。MemoryOS 选了其中一条：一个共享记忆层，结束对话时把要点写下来，下一段对话无论在哪个 AI 里都能带回去。赌的是"选哪条路"，不只是某个功能。

选定记忆层这条路之后，两个关键决策定义了它的形态：(1) 记忆文件存在用户自己的电脑里，不在任何厂商的云账户上——没人愿意自己的笔记散落在不同公司的服务器；(2) AI 起草更新但每一次写入都由用户确认——AI 一旦悄悄改了你的笔记，信任就崩了。整套产品定义、设计、工程都是一个人完成的；Case Study 完整拆解 5 个核心决策，以及"什么样的用户反馈会推翻这些判断"。

From global industrial data down to a single 8×8 cell at Dagenham Dock, the thesis is laid out as one explorable interface. Every scroll, every layer toggle, every inference call is another round of reasoning over the same ground. What used to be an opaque process is broken down into legible steps — less looking at a project, more operating a reasoning tool: the final judgement comes from human and algorithm together, not the designer alone.

The Entropy Atlas — the n8n-orchestrated evidence layer of ~1,000 East-London post-industrial sites — is included inside this demo as the site-evidence layer.

从全球尺度的行业数据，到 Dagenham Dock 上一格 8×8 网格的具体判断，整个毕设被整理成一个可逐步操作的界面。每一次滚动、每一次图层切换、每一次分析调用，都是对同一片场地的一次重新判断。原本看不透的决策过程被拆解成逐层可读的步骤——与其说是浏览一个项目，不如说是操作一套判断工具：最终结论由人与算法共同完成，而非设计师单方决定。
