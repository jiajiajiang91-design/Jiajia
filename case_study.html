MemoryOS

跨 AI 的本地工作记忆 —— 按项目整理, 记忆保持现时。

我用一套 Markdown 文件夹在 ChatGPT、Claude、Cursor、Gemini 之间手动同步上下文 3 个月。每次开新对话都要重新告诉 AI 我是谁、上次到哪了, 复制粘贴自己是谁三个月之后会想砸键盘。

ChatGPT Memory 记住的是"你是谁", Claude Projects 只对 Claude 生效, Notion AI 锁在自己的工作区。但没有工具帮你记住"这件事做到哪了、为什么这么决定的" —— 我把这件事做成了一个桌面 app。

这个项目训练的能力

定义一个 AI 工作流问题 → 设计最小可验证闭环 → 交付可运行的桌面 Demo → 基于真实使用摩擦持续迭代。This project trained me to define an AI workflow problem, design a minimum testable loop, ship a working desktop demo, and iterate based on real usage friction.

痛点 — 复制粘贴自己是谁三个月

3 个月里我每天在 4 个 AI 之间切换。每次开新对话都要先粘 200 行"我是谁 / 上次到哪了"——一天 5-10 次。

更深的痛不是粘贴慢，是没有产品帮你记住"这件事做到哪了、为什么这么决定"。ChatGPT Memory 记住"你喜欢简洁回答"，Claude Projects 只对 Claude 生效——它们帮 AI 认识你，但不管跨 AI 的工作进展。

把工作记忆从各个 AI 里抽出来、按项目整理、存在用户自己电脑上——这件事没人做。所以我做了。

市场定位 — 为什么是这个空白象限

右上角（跨 AI + 数据在用户手里）是空白象限。现有产品要么只对一个 AI 生效（ChatGPT Memory），要么绑定平台（Notion AI）。MemoryOS 落在这里——用户在任意 AI 之间切换都能续上工作，数据始终在自己电脑上。

用户旅程 — 谁用、怎么用

USER · INTERACTION

MemoryOS 服务一类核心用户: 普通 AI 用户 —— 在多个 AI 之间切换工作, 已经感到"复制粘贴自己是谁"的真实痛感, 但非技术背景, 不会自建 RAG 或写 prompt template。

工作流是一个用户主动驱动的 5 步循环:

  1. 01
    Start

    在 MemoryOS 选当前项目 → 点【复制开始对话指令】→ 粘到任意 AI。AI 读取上下文, 30 秒续上。

  2. 02
    Work

    正常和 AI 工作, MemoryOS 不参与。

  3. 03
    End

    工作差不多了 → 在 MemoryOS 点【复制结束对话指令】→ 选当前在用的 AI (ChatGPT / Claude / Gemini / Grok / Cursor / Codex / DeepSeek / Kimi 或自定义) → 粘到 AI。

  4. 04
    AI 总结

    AI 按 MemoryOS 提供的标准化模板, 输出一份结构化对话总结 (固定 Markdown 格式)。

  5. 05
    Review → Save

    用户把总结复制回 MemoryOS, 点【+ 导入对话总结】, 按风险分级勾选要写入的内容, Save。

注意第 5 步的设计选择: 不是 AI 直接写文件, 是用户勾选 checkbox 确认每一行写入。这是 MemoryOS 最重要的产品立场 —— AI 总结、用户确认。下一节展开。

系统架构 — 三层全本地，AI 在边界之外

  1. 1. 存储层 INPUT

    用户电脑上的 Markdown 文件（about_me.md + 每个项目的 00_context.md / decisions.md / sessions/*）。不是数据库——拷贝文件夹就是完整备份，任何编辑器都能打开。

  2. 2. 应用层 SYSTEM LOGIC

    Tauri + React + TS。负责：容错解析 / Superseded 记忆合并 / 风险分级导入 / App 内文件编辑 / 中英双语 / 回收站删除 + Undo / 反馈通道。

  3. 3. 桥接层 OUTPUT

    用剪贴板桥接所有 AI。MemoryOS 把上下文写进剪贴板，用户粘到任意 AI；AI 输出复制回来，用户勾选保存——换 AI 不用重新配置，30 秒续上。

AI 调用边界 — 哪一步用 AI，哪一步根本不用

关键决策 — 六次取舍

01
数据在用户电脑 vs 云同步

选本地——用户拷贝文件夹就是完整备份，不需要账号，不依赖任何服务。

验证：种子用户说"冲着本地才用"→ 成立
02
剪贴板桥接 vs 自动抓取

选剪贴板。代价：每次多 3 次点击。收益：用户完整控制数据，换 AI 零成本。

03
Markdown 纯文本 vs 数据库

选 Markdown。用户随时可以删掉 MemoryOS，用任何编辑器继续。靠"体验更好"留人。

04
风险分级导入，不做自动写

dogfood 时 AI 加了一条错误假设，两周后才发现。改成三级风险：低（默认勾）/ 中（review 提示）/ 高（默认不勾 + 警告）。

05
不加 RAG / Agent

每个项目就几 KB，问题本质是"怎么让记忆保持现时"，不是"怎么检索"。用户要的是控制感，不是自动化。

06
Superseded 合并而非 diff

AI 标出过时内容 → app 展示新旧对比 → 用户确认 → 4 下点击完成记忆更新。代价：依赖 AI 标注质量。

已知风险 — 我打算怎么验证 / 怎么 fallback

3 条 disconfirming evidence 我已经知道, 不藏:

用户可能不愿意手动 handoff。

如果种子用户里多数反馈"复制粘贴太烦", 红线需要重判——可能切到"浏览器插件只读模式 + 用户每次确认", 而不是完全自动抓取。

AI 平台可能自己做项目级记录。

MemoryOS 的价值在"跨所有 AI + 数据在本地"——即使各家自带了项目记录, 用户仍然需要一个不绑定厂商的统一入口。
